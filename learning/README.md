# 제조 AI 연결 실습

## 앱의 역할

|앱|실행|역할|
|---|---|---|
|수집기|Start.cmd|Modbus·OPC UA·로봇·아두이노 데이터 수집|
|Learning Studio|StartLearning.cmd|공장 배치·연결선·장치 매핑·동기화·AI 실습|
|MES|StartMES.cmd|설비·품목·작업지시·LOT·검사 결과|
|POP|StartPOP.cmd|작업지시 조회·작업 상태·실적·비가동 사유|

MES와 POP는 별도 프로세스/화면이며 같은 학습 DB를 사용합니다. 수집기는 독립적으로 동작합니다. Studio의 **MES 열기 / POP 열기** 버튼도 사용할 수 있습니다.

## 1교시: 장치와 생산 현장 연결

1. 수집기에서 **가상 공장 추가 → 전체 수집 시작 → 학습 앱 연결 API**를 누릅니다.
2. MES에서 `CELL-01` 설비와 `PART-01` 품목을 등록합니다.
3. Studio에서 **기본 블록 놓기**를 누릅니다. 처음에는 선이 없습니다.
4. 일반 모드에서 블록을 드래그해 배치합니다. **연결 모드**를 켜고 수집 블록 → MES 블록을 클릭해 선을 만듭니다. MES → POP, MES → AI, POP → AI 선도 만들어 전체 흐름을 표현합니다.
5. 수집 블록의 설비 코드는 `DEMO-PLC`, MES 블록은 `CELL-01`인지 확인합니다. 다른 장치를 연결하려면 블록을 선택해 **블록 수정**에서 코드를 바꿉니다. 이미 연결된 블록은 선을 먼저 해제해야 합니다.
6. **수집기·장치 매핑** 탭에서 `http://127.0.0.1:8808`의 연결을 확인합니다.
7. **장치 매핑**으로 `DEMO-PLC → CELL-01`을 지정합니다. 온도 센서는 생산 카운터로 지정하지 않습니다.
8. **지금 동기화**를 누르거나 2초 자동 동기화를 켭니다.

수집→MES 선과 명시적 장치 매핑이 실제 데이터 라우팅에 사용됩니다. MES→POP/AI 등의 선은 학습 흐름을 설명하는 배치도이며 그 선만으로 앱 간 명령이나 네트워크 연결이 생성되지는 않습니다. MES/POP는 학습 서비스와 DB를 통해 실적을 공유합니다.

매핑이 없는 데이터는 건너뛰고 수집기 원본에는 남깁니다. 매핑을 추가한 뒤 **처음부터 다시 읽기 → 동기화**하면 가져올 수 있습니다. 이미 가져온 데이터는 고유 ID로 중복 저장하지 않습니다. 과거에 가져온 데이터의 매핑은 새 매핑으로 덮어쓰지 않습니다.

## 2교시: MES 작업과 POP 실적

1. MES에서 작업지시 `WO-001`, LOT `LOT-001`, 설비 `CELL-01`을 등록합니다.
2. POP에서 작업지시를 선택하거나 작업지시 코드를 바코드 입력칸에 넣고 Enter를 누릅니다. 일반 키보드 방식 바코드 스캐너 입력에 대응하며 실물 스캐너 시험은 하지 않았습니다.
3. 작업자를 입력하고 **작업 시작**을 누릅니다.
4. 센서를 수집·동기화하는 동안 **실적 등록**에서 이번에 추가한 양품/불량 수량을 입력합니다. 누적 수량을 다시 입력하는 방식이 아닙니다.
5. **일시 정지** 시 비가동 사유를 입력하고 **작업 재개** 후 작업을 계속합니다.
6. **작업 완료** 후 MES에서 같은 작업의 실적을 확인하고, 확인된 품질에 따라 normal/defect/unknown을 판정합니다.
7. 다른 LOT도 반복해 생산합니다. 한 설비에 진행 중/일시 정지 작업은 하나만 허용합니다.

측정값과 실적은 서로 다른 테이블입니다. 센서값에 작업 시각·MES 설비가 맞으면 학습 CSV에서 작업/LOT를 결합합니다. 작업 시작/완료 구간 전체에 연결되며, 일시 정지 중의 센서값도 해당 작업에 포함될 수 있습니다. 실제 학습에서 정지 구간을 제외하려면 POP 이벤트 시각을 함께 활용해야 합니다. 수집기 자체의 production_runs와 학습 MES의 jobs는 별개의 이력입니다.

### 양품 카운터 연결

장치의 **양품 누적 개수**를 나타내는 정수형 센서만 매핑의 카운터로 지정합니다. 전체 생산 개수만 제공하는 장치에는 이 기능을 그대로 적용하면 양품/불량 해석이 틀릴 수 있습니다.

- 최초값은 기준선으로만 저장하고 수량에 더하지 않습니다.
- 다음 값과의 차이만 해당 작업의 추가 양품으로 기록합니다.
- 카운터가 감소하면 reset으로 표시하고 해당 구간은 0 증가로 처리합니다. 초기화 사이의 실제 생산량을 추정하지 않습니다.
- 재수신·동기화 재실행은 중복 집계하지 않습니다.
- 일시 정지/재개 뒤에는 새 기준선을 잡아 정지 중 증가를 생산 실적으로 추정하지 않습니다.
- 카운터 연결 중에는 양품 수동 입력을 막습니다. 불량은 수동으로 추가할 수 있습니다.
- 모든 장비의 오버플로·롤오버 규칙을 자동 인식하지는 않습니다.

가상 공장의 온도·진동·각도는 카운터가 아닙니다. 별도 장치가 제공하는 실제 정수 누적 양품 센서가 있을 때 사용합니다.

## 3교시: 제조 AI 데이터와 평가

1. Studio의 **제조 AI 실습**에서 센서를 선택합니다.
2. 서로 다른 작업/LOT 2개 이상이 필요합니다. 작업 순서 앞 70%를 학습 구간, 뒤 구간을 평가 구간으로 분리합니다. 학습 구간에서는 normal 판정과 good 품질 표본만 사용합니다.
3. **정상 기준선 학습·평가**를 누릅니다. 정상 평균과 표준편차를 구하고 평균에서 `max(kσ, 평균 절댓값의 0.1%, 1e-6)`를 초과하는지 평가합니다. 화면의 기준선 배수 k는 기본 3이며 0.5~6으로 바꿀 수 있습니다. 배수를 줄이면 더 작은 차이에도 경보가 납니다.
4. 학습/평가 작업 ID, 정상 오탐(FP), 불량 미탐(FN), 불량 감지(TP), 정상 통과(TN)를 비교합니다. 같은 작업이 양쪽에 들어가지 않습니다.
5. **MES 연결 학습 CSV 저장**으로 센서·시각·품질·설비·작업·LOT·품목·판정을 함께 내보냅니다. 판정과 작업/LOT 식별자를 정답을 유추하는 모델 입력으로 사용하지 않도록 주의합니다.

이 기능은 **단일 센서의 정상 기준선 학습**입니다. 고장까지 남은 시간 예측이나 검증된 예지보전 모델이 아닙니다. LOT 전체 판정을 각 표본의 정답으로 사용하는 교육용 평가이므로 실제 불량이 발생한 정확한 시점을 보증하지 않습니다. 많은 센서 표본이 있어도 같은 LOT의 표본은 독립된 검사 건수가 아닙니다.

### 장비 없는 빠른 실습

**예제 선택**에서 품질 이상·데이터 드리프트·생산량을 고려한 에너지·누락/센서 오류 중 하나를 고릅니다. 각각 가상 LOT 10개를 생성합니다. 예제끼리는 별도 데이터셋·설비 코드로 구분하며 수집기에는 쓰지 않습니다. **시계열 트렌드**에서 품질·이동평균·학습 기준선·평가 시작을 확인합니다.

**트윈·근거 검색**에는 공정 주기 변경 What-if와 교육용 문서의 근거 검색 실습이 있습니다. LLM·실제 설비 매뉴얼은 사용하지 않습니다. [6개 주제의 실습 교안과 과제](LESSONS.md).

## 배치 저장과 학습자별 환경

**배치 저장**은 블록 위치·역할·선·설비/품목 기준정보·활성 매핑을 JSON으로 저장합니다. **배치 불러오기**는 기존 자료를 지우지 않고 추가합니다. 작업 실적·측정값·학습 모델은 이 파일에 포함하지 않습니다.

같은 설치 폴더의 MES·POP·Studio는 `data/learning.sqlite3`를 공유합니다. 다른 학습자나 프로젝트는 별도 설치 폴더를 사용하거나, 시작 전에 `OPENSIGNAL_LEARNING_DB` 환경변수를 다른 SQLite 파일의 절대경로로 지정합니다. Studio에서 여는 MES/POP는 해당 DB 경로를 이어받습니다.

## 저장·연결 구조

- 수집 DB: `data/manufacturing.sqlite3`, 수집기만 기록.
- 읽기 전용 API: 127.0.0.1:8808, `GET /v1/catalog`, `GET /v1/samples?after_id=0&limit=500`. 최대 1,000개/요청. 설정·비밀번호는 전달하지 않습니다.
- 학습 DB: `data/learning.sqlite3`, [스키마](schema.sql). 수집 원본을 고유 데이터셋/측정 ID로 가져와 MES 설비와 연결합니다.
- MES/POP: 별도 앱에서 동일 학습 서비스를 사용하며 상태 전이와 이벤트 ID, DB 트랜잭션으로 실적을 기록합니다.
- 모델 결과: 학습 DB models에 기준선 파라미터·대상 센서·분할 작업·평가 결과를 저장합니다.

운영 화면 대신 API만 실행하려면 프로젝트 폴더에서 `python collector_api.py`를 사용할 수 있습니다. 수집 DB가 먼저 생성되어 있어야 합니다. 이미 수집기에서 API를 시작했다면 같은 포트로 다시 실행하지 마세요.

이 버전은 같은 PC에서의 학습용입니다. 교실 전체의 네트워크 서버·사용자 인증·권한·ERP 연동·재고/BOM·법정 생산 이력·실물 장비 장시간 운용은 제공하거나 검증하지 않았습니다. 동기화하지 않은 데이터는 학습 화면에 자동으로 나타나지 않습니다. 실제 설비 제어 명령은 보내지 않습니다.

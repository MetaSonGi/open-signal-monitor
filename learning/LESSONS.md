# 제조 AI 예제 · 시계열 트렌드 실습

확인일: 2026-10-20. 데이터 4종과 조작 도구 2종, 총 6개 주제입니다. 외부 계정·AI API 키·실물 장비 없이 사용할 수 있습니다.

## 시작

`StartLearning.cmd → 예제 선택 → 주제 선택 → 예제 데이터 만들기`를 누릅니다. 자동으로 **시계열 트렌드**로 이동합니다. 센서를 고르고 이동평균 표본 수를 바꾸어 보세요. **제조 AI 실습**에서 같은 센서의 기준선 배수(기본 3σ)를 정하고 학습·평가합니다. 학습 후 트렌드에 기준선과 평가 시작 선이 표시됩니다.

각 데이터 예제는 LOT 10개, LOT당 24개 시점입니다. 앞 7개 LOT를 학습 구간, 뒤 3개 LOT를 평가 구간으로 사용하며 학습에는 normal 판정·good 품질만 포함합니다. 여러 센서가 있으면 같은 시각에 센서별 행을 저장합니다.

모든 데이터·문서는 교육용으로 생성했습니다. 아래 성능 수치는 이 합성 예제와 구현이 맞는지 확인하는 기준이며 실제 공장 성능의 근거가 아닙니다.

## 01 · 품질 이상 탐지

**질문:** 작은 차이까지 감지하도록 설정하면 무조건 좋은 모델일까요?

1. 품질 이상 예제를 생성하고 진동 RMS 센서를 선택합니다.
2. 3σ로 학습해 정상 오탐(FP)과 불량 미탐(FN)을 기록합니다.
3. 0.5σ로 다시 학습하고 트렌드의 기준선 폭이 좁아지는지 확인합니다.
4. 오탐이 늘었을 때 검사 비용·작업 중단 비용을 어떻게 고려할지 설명합니다.

뒤 3개 평가 LOT는 정상 1개·불량 2개입니다. 기본 예제에서 진동 3σ는 정상 24개를 통과하고 불량 48개를 감지합니다. 0.5σ는 정상 오탐이 늘어납니다. LOT 전체 판정을 표본에 연결한 교육용 평가이므로 48개의 독립된 불량 제품을 검증한 결과는 아닙니다.

**과제:** 같은 LOT를 학습·평가에 나누어 넣으면 왜 평가가 낙관적일 수 있는지 설명하세요.

## 02 · 데이터 드리프트

**질문:** 센서 평균이 변하면 제품도 불량일까요?

1. 드리프트 예제를 만들고 온도 추이를 확인합니다.
2. 학습·평가 구간의 위치와 정상 판정을 MES 화면에서 비교합니다.
3. 정상 기준선 모델이 평가 구간에서 내는 오탐을 확인합니다.
4. 원인을 환경·운전 조건·센서 보정·실제 품질 변화로 나누어 조사 계획을 만듭니다.

이 예제의 모든 LOT는 normal입니다. 입력 분포만 바꿨기 때문에 기본 모델은 정상 표본에도 경보를 냅니다. 자동으로 새 평균을 정상이라고 받아들이는 대신 새 조건과 판정 자료를 확인해야 합니다. 이 실습은 입력 데이터 드리프트이며 모든 종류의 개념 드리프트를 구현한 것은 아닙니다.

## 03 · 생산량을 고려한 에너지

**질문:** 소비 전력이 높으면 비효율이라고 판단해도 될까요?

1. 에너지 예제의 소비 전력(W), 생산 속도(part/h), 개당 에너지(Wh/part)를 차례로 봅니다.
2. 소비 전력으로 학습하고 평가 구간 첫 정상 LOT의 오탐을 확인합니다.
3. 개당 에너지로 학습해 같은 LOT의 결과를 비교합니다.
4. 어떤 운전 상태·제품 종류를 추가로 맞춰 비교해야 할지 적습니다.

정상 LOT의 생산 속도를 높여 전력도 증가시켰습니다. 이 데이터는 `전력 W = 생산 속도 part/h × 개당 에너지 Wh/part` 관계로 구성했습니다. 개당 에너지 특징은 이 예제에서 정상 생산량 증가와 비효율을 구분합니다. 모든 설비에서 단순 비율 하나로 효율을 판정할 수 있다는 뜻은 아닙니다.

## 04 · 누락·오류·데이터 품질

**질문:** 누락을 0으로 채우면 그래프와 평균은 어떻게 달라질까요?

1. 데이터 품질 예제를 생성합니다. 회색 표시에서 missing/device_bad/stale을 확인합니다.
2. 잘못된 전처리 비교 평균과 유효값 평균을 비교합니다.
3. **good 품질만 그리기**를 켜고 정상 온도의 추이를 확인합니다.
4. 학습 표본 수가 원본 표본 수보다 적은 이유를 설명합니다.

예제는 총 240행이며 good 표본 180개, 불량 품질·누락 60개입니다. 모델은 학습 126개·평가 54개의 good 값만 사용합니다. 그래프의 품질 표시와 CSV 원본은 오류/누락을 보존합니다. 오류값과 0 채움을 함께 사용하는 비교 평균은 의도적으로 잘못된 전처리 사례입니다.

## 05 · 생산 라인 What-if

**위치:** 트윈·근거 검색 → 생산 라인 What-if.

기준 공정 주기는 30·60·45초입니다. 공정 1을 10초로 줄일 때와 공정 2를 40초로 줄일 때를 비교하세요. 후자는 병목이 공정 3으로 이동합니다. 가동률과 양품률도 바꿔 결과를 비교합니다.

**학습 목표:** 병목과 비병목 개선을 구분하고, 모델의 가정을 적는 것.

직렬 라인의 정상상태 근사식 `예상 양품 = 3600 / 최대 공정 주기 × 시간 × 가동률 × 양품률`을 사용합니다. 연속적인 기대값이므로 실제 개수와 일치하지 않을 수 있습니다. 버퍼·물류·시동·교체·병렬 공정·고장 상관관계를 계산하는 시뮬레이터나 실시간 디지털트윈은 아닙니다. 수집기나 로봇에 제어 명령을 보내지 않습니다.

## 06 · 근거 검색 / 산업용 RAG의 기초

**위치:** 트윈·근거 검색 → 근거 검색 / RAG 기초.

1. “진동이 높고 오탐이 생긴다”를 질문합니다.
2. 문서 ID, 매칭 단어, 근거 문장이 함께 표시되는지 확인합니다.
3. “외계 행성 이름”처럼 자료에 없는 질문을 입력해 근거가 없다고 답하는지 확인합니다.
4. 실제 매뉴얼을 연결한다면 문서 버전·설비 모델·검색 정확도·답변 근거를 어떻게 관리할지 설계합니다.

교육용 가상 절차 4건을 키워드로 검색합니다. LLM의 답변 생성이나 임베딩·벡터 검색은 구현하지 않았습니다. 이 단계는 RAG에서 검색과 근거 확인의 역할을 배우는 축소 예제입니다. 가상 문서는 실제 정비 작업 지시가 아닙니다.

## 트렌드 그래프 읽기

- 파란 선: good 표본. 주황 선: 연속된 good 표본의 이동평균.
- 회색 표시: 품질이 나쁜 값 또는 누락. 0으로 바꾸지 않습니다.
- 초록 점선: 선택 센서의 최근 학습 기준선. 다른 센서 모델의 선을 섞지 않습니다.
- 평가 시작 선: 학습에 쓰지 않은 작업의 시작 위치.
- 실제 UTC 시각을 축으로 사용합니다. LOT 경계와 품질 불량 구간은 선을 연결하지 않습니다.
- 화면은 최근 2,000개 표본으로 제한하지만 학습은 선택 센서의 전체 해당 자료를 사용합니다. 이동평균은 시각화용이며 학습 입력을 자동으로 바꾸지 않습니다.

## 데이터만 저장하기

예제 선택 탭의 **이 예제 CSV 저장**은 선택한 예제만 CSV와 `.manifest.json`으로 저장합니다. 실제 수집 자료나 다른 예제를 섞지 않습니다. 명령으로 일괄 생성하려면:

```powershell
.\.venv\Scripts\python.exe -m learning.scenarios --export-dir teaching_examples --lesson all
```

quality.csv 480행, drift.csv 240행, energy.csv 720행, data_quality.csv 240행을 생성합니다. 각 파일에 데이터셋·설비·시각·센서·단위·품질·작업지시·LOT·판정이 포함됩니다. 임시 DB에서 만들고 학습 DB와 수집 DB에는 쓰지 않습니다.

## 최근 공개 자료와의 연결

여기서 말하는 트렌드는 시계열 추이와 제조 AI 학습 주제를 함께 뜻합니다. 아래 공개 자료가 다루는 데이터 연계·검증·드리프트·검색 근거를 기초 실습으로 구성했으며, 산업 도입 순위나 시장 점유율을 주장하는 목록은 아닙니다.

- [NIST 제조 디지털트윈 프로젝트](https://www.nist.gov/programs-projects/digital-twins-advanced-manufacturing): 데이터 연계·추적성과 모델 검증을 다룹니다. 이 실습의 수집→MES/POP→학습 연결과 모델 가정 확인에 대응합니다.
- [NIST Digital Twins Workshops Summary Report (2026)](https://www.nist.gov/publications/digital-twins-workshops-summary-report): 디지털트윈의 공통 개념과 적용 과제를 정리한 공개 보고서입니다.
- [NIST AI RMF Playbook: Measure](https://airc.nist.gov/airmf-resources/playbook/measure/): 모델의 조건 변화·한계와 측정·평가를 검토하는 배경 자료입니다.
- [NIST TREC 2025 RAG 트랙](https://pages.nist.gov/trec-browser/trec34/rag/overview/): 검색·생성의 평가를 다룹니다. 본 프로그램의 검색 도구가 이 트랙의 모델이나 평가 시스템을 재현한 것은 아닙니다.
